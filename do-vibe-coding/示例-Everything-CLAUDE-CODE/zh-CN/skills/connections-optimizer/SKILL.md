# 连接优化器

重新组织用户的网络，而不是将出站视为单向勘探列表。

该技能处理：

- X 清理和扩展之后
- LinkedIn 关注和连接分析
- 审查优先修剪队列
- 添加并遵循建议
- 热路径识别
- 以用户真实声音生成 Apple Mail、X DM 和 LinkedIn 草稿

## 何时激活

- 用户想要修剪他们的 X 关注者
- 用户想要重新平衡他们关注的人或保持联系的人
- 用户说“清理我的网络”、“我应该取消关注谁”、“我应该关注谁”、“我应该与谁重新连接”
- 外展质量取决于网络结构，而不仅仅是冷名单的生成

## 所需的输入

收集或推断：

- 当前的优先事项和积极的工作
- 目标角色、行业、地理区域或生态系统
- 平台选择：X、LinkedIn 或两者
- 请勿触摸列表
- 模式：“light-pass”、“default”或“aggressive”

如果用户未指定模式，则使用“默认”。

## 工具要求

### 首选

- 用于 X 图检查和最近活动的“x-api”
- 用于目标发现和热路径排名的“领先情报”- 当用户希望独立于更广泛的潜在客户工作流程对桥梁价值进行评分时，使用“社交图排名器”
- Exa/深入研究以丰富个人和公司
- 起草出站前的“品牌声音”

### 后备方案

- 用于 LinkedIn 分析和起草的浏览器控件
- 如果 API 覆盖范围受到限制，则 X 的浏览器控制
- 当电子邮件是正确的渠道时，通过桌面自动化进行 Apple Mail 或 Mail.app 起草

## 安全默认值

- 默认是review-first，绝不盲目自动剪枝
- X：仅删除用户关注的帐户，从不删除关注者
- LinkedIn：将一级连接删除视为手动审核优先
- 不要自动发送 DM、邀请或电子邮件
- 在任何应用步骤之前发出排名的行动计划和草案

## 平台规则

### X

- 相互比单向跟随更具粘性
- 可以更积极地修剪非追随者
- 严重不活跃或消失的帐户应该很快就会浮出水面
- 参与度、信号质量和桥梁价值比原始关注者数量更重要

### 领英

- 如果用户确实拥有 LinkedIn API 访问权限，则 API 优先
- 当 API 访问缺失时，浏览器工作流程必须正常工作
- 区分出站跟随和接受的一级连接- 出站跟随可以更自由地修剪
- 接受的一级连接应默认进行审核，而不是自动删除

## 模式

### `光通行证`

- 仅修剪高置信度低值单向跟随
- 将其余部分显示出来以供审查
- 生成一个小的添加/关注列表

### `默认`

- 平衡修剪队列
- 平衡保留列表
- 排名添加/关注队列
- 在有用的情况下起草热情的介绍或直接外展

### `侵略性`

- 更大的修剪队列
- 对过时的非跟进的容忍度较低
- 申请前仍需经过审查

## 评分模型

使用这些积极信号：

- 互惠
- 最近的活动
- 与当前优先事项保持一致
- 网桥值
- 角色相关性
- 真实的订婚历史
- 最近的存在和响应能力

使用这些负面信号：

- 帐户消失或被遗弃
- 陈旧的单向跟随
- 非优先主题集群
- 低值噪声
- 反复无反应
- 当存在许多更好的替代品时，没有后续行动

互惠桥和真正的热路径桥应该受到比单向桥更小的惩罚。

## 工作流程

1. 确定优先事项、禁止触及的限制条件和选定的平台。
2. 拉取当前关注/连接库存。3. 对修剪候选者进行评分，并给出明确的理由。
4. 分数保留候选人有明确的理由。
5. 使用“领先情报”加上研究面对扩展候选者进行排名。
6、匹配正确的通道：
   - X DM 提供温暖、快速的社交接触点
   - 用于专业图形邻接的 LinkedIn 消息
   - 用于更高上下文介绍或外展的 Apple Mail 草稿
7. 在起草消息之前运行“brand-voice”。
8. 在任何应用步骤之前返回审核包。

## 出站规则

- 默认电子邮件路径是 Apple Mail / Mail.app 草稿创建。
- 不自动发送。
- 根据热情度、相关性和上下文深度选择频道。
- 当电子邮件或不外展是正确的做法时，不要强迫发私信。
- 草稿应该听起来像用户，而不是像自动销售副本。

## 相关技能

- “品牌语音”可重复使用的语音配置文件
- 用于独立桥梁评分和热路径数学的“社交图排名器”
- 用于加权目标和热路径发现的“领先情报”
- 用于 X 图访问、起草和可选应用流程的“x-api”
-“内容引擎”，当用户还希望围绕网络移动公开发布内容时
