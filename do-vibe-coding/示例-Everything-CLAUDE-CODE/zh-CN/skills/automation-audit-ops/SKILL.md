# 自动化审计操作

当用户询问哪些自动化正在运行、哪些作业被破坏、哪里存在重叠、或者哪些工具和连接器现在实际上正在做有用的工作时，请使用此选项。

这是审核优先的操作员技能。这项工作是在重写任何内容之前生成一个有证据支持的清单和一个保留/合并/剪切/修复下一个建议集。

## 技能栈

在相关时将这些 ECC 原生技能引入工作流程：

- 用于连接器、MCP、挂钩和应用程序库存的“工作空间表面审计”
- 当审计需要将实时回购事实与持久背景相协调时，进行“知识操作”
- 当答案取决于 CI、预定工作流程、问题或 PR 自动化时，使用“github-ops”
- 当真正的问题是同级应用程序存储库中的 webhook 扇出、排队作业或账单消耗时，使用“ecc-tools-cost-audit”
- 当必须将本地库存与当前平台支持或公共文档进行比较时，进行“研究操作”
- “验证循环”用于证明修复后状态，而不是依赖于假设的恢复

## 何时使用

- 用户询问“我有什么自动化功能”、“什么是实时的”、“什么是损坏的”或“什么是重叠的”- 任务涵盖 cron 作业、GitHub Actions、本地挂钩、MCP 服务器、连接器、包装器或应用程序集成
- 用户想知道什么是从另一个代理系统移植的以及什么还需要在 ECC 内重建
- 工作区积累了多种方法来完成同一件事，并且用户想要一个规范通道

## 护栏

- 开始只读，除非用户明确要求修复
- 分开：
  - 配置的
  - 已验证
  - 最近验证
  - 陈旧或破损
  - 完全失踪
- 不要仅仅因为技能或配置引用了某个工具就声称它是可用的
- 在证据表存在之前不要合并或删除重叠表面

## 工作流程

### 1. 盘点真实表面

在理论化之前阅读当前的实时表面：

- 回购挂钩和本地挂钩脚本
- GitHub Actions 和预定工作流程
- MCP 配置和启用的服务器
- 连接器或应用程序支持的集成
- 包装器脚本和特定于存储库的自动化入口点

按表面对它们进行分组：

- 本地运行时
- 回购 CI/自动化
- 连接的外部系统
- 消息/通知
- 计费/客户运营
- 研究/监测

### 2. 按活动状态对每个项目进行分类对于每个出现的自动化，标记：

- 配置的
- 已验证
- 最近验证
- 陈旧或破损
- 失踪

然后对问题类型进行分类：

- 主动破损
- 授权中断
- 陈旧状态
- 重叠或冗余
- 缺乏能力

### 3.追踪证明路径

用具体来源支持每一个重要的主张：

- 文件路径
- 工作流程运行
- 钩子日志
- 配置条目
- 最近的命令输出
- 准确的故障签名

如果当前状态不明确，请直接说明，而不是假装审核已完成。

### 4. 以 keep / merge / cut / fix-next 结束

对于每个重叠或可疑表面，返回一个调用：

- 保留
- 合并
- 切
- 修复下一步

价值在于将嘈杂的自动化压缩到一个规范的 ECC 通道中，而不是保留每条历史路径。

## 输出格式```text
CURRENT SURFACE
- automation
- source
- live state
- proof

FINDINGS
- active breakage
- overlap
- stale status
- missing capability

RECOMMENDATION
- keep
- merge
- cut
- fix next

NEXT ECC MOVE
- exact skill / hook / workflow / app lane to strengthen
```
## 陷阱

- 当可以读取实时库存时，不要凭记忆回答
- 不要将“存在于配置中”视为“工作”
- 在命名损坏的高信号路径之前，不要修复较低值的冗余
- 如果用户首先要求库存，请勿将任务扩展为回购重写

## 验证

- 重要的主张引用了活生生的证明路径
- 每个浮出水面的自动化都标有清晰的实时状态类别
- 最终建议区分keep / merge / cut / fix-next
