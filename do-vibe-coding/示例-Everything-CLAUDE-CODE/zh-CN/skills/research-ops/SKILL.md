# 研究行动

当用户要求研究当前的内容、比较选项、丰富人员或公司或将重复查找转变为受监控的工作流程时，请使用此功能。

这是存储库研究堆栈的运算符包装器。它不能替代“深度研究”、“exa-search”或“市场研究”；它告诉您何时以及如何一起使用它们。

## 技能栈

在相关时将这些 ECC 原生技能引入工作流程：

- `exa-search` 用于快速发现当前网络
- 带有引文的多源综合“深度研究”
- “市场研究”，最终结果应该是推荐或排名决策
- 当任务是针对人员/公司而不是一般研究时，称为“领先情报”
- 当结果应该随后存储在持久上下文中时的“知识操作”

## 何时使用

- 用户说“研究”、“查找”、“比较”、“我应该和谁交谈”或“最新消息是什么”
- 答案取决于当前的公开信息
- 用户已经提供了证据并希望将其纳入新的推荐中
- 该任务可能会重复出现，以至于它应该成为一个监视器而不是一次性查找

## 护栏- 当新搜索很便宜时，不要从陈旧的记忆中回答当前的问题
- 分开：
  - 来源事实
  - 用户提供的证据
  - 推论
  - 推荐
- 如果答案已经在本地代码或文档中，则不要启动重量级研究通行证

## 工作流程

### 1. 从用户已经给你的内容开始

将任何提供的材料标准化为：

- 已经证实的事实
- 需要验证
- 开放式问题

如果用户已经构建了模型的一部分，请勿从零重新开始分析。

### 2. 对询问进行分类

搜索前选择正确的车道：

- 快速的事实答案
- 比较或决定备忘录
- 引导/浓缩通行证
- 经常性监测候选人

### 3. 首先采取最轻的有用证据路径

- 使用“exa-search”进行快速发现
- 当综合或多来源很重要时升级为“深入研究”
- 当结果应以建议结束时使用“市场研究”
- 当真正的要求是目标排名或热路径发现时，交给“领先情报”

### 4. 具有明确证据边界的报告

对于重要的主张，请说明它们是否：

- 来源事实
- 用户提供的上下文
- 推论
- 推荐对新鲜度敏感的答案应包括具体日期。

### 5. 决定任务是否应保持手动

如果用户可能会反复询问相同的研究问题，请明确说明并推荐监控或工作流程层，而不是永远重复相同的手动搜索。

## 输出格式```text
QUESTION TYPE
- factual / comparison / enrichment / monitoring

EVIDENCE
- sourced facts
- user-provided context

INFERENCE
- what follows from the evidence

RECOMMENDATION
- answer or next move
- whether this should become a monitor
```
## 陷阱

- 不要将推论混合到来源事实中而不对其进行标记
- 不要忽视用户提供的证据
- 不要使用繁重的研究通道来解决本地存储库上下文可以回答的问题
- 不要给出没有日期的新鲜度敏感答案

## 验证

- 重要主张按证据类型标记
- 新鲜度敏感的输出包括日期
- 最终推荐符合实际使用的研究模式
