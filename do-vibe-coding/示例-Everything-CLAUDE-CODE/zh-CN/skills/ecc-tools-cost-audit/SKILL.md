# ECC 工具成本审计

当用户怀疑 ECC Tools GitHub 应用程序正在消耗成本、过度创建 PR、绕过使用限制或将免费用户路由到高级分析路径时，请使用此技能。

这是同级 [ECC-Tools](../../ECC-Tools) 存储库的集中操作员工作流程。它不是通用的计费技能，也不是存储库范围内的代码审查通行证。

## 技能栈

在相关时将这些 ECC 原生技能引入工作流程：

- “自主循环”，用于跨 Webhook、队列、计费和重试的有界多步骤审核
- “代理工程”，用于将请求路径跟踪为离散的、可证明的单元
- 当回购行为和客户影响数学必须完全分开时，“客户计费操作”
- 在发明助手或重新实现存储库本地实用程序之前“搜索优先”
- 当授权、使用门、权利或秘密被触及时进行“安全审查”
- 用于证明重新运行安全性和准确的修复后状态的“验证循环”
- 当修复需要在工作线程、路由器或计费路径中进行回归覆盖时，使用“tdd-workflow”

## 何时使用

- 用户表示 ECC 工具消耗率、PR 递归、过度创建 PR、绕过使用限制或高级模型泄漏- 该任务位于同级“ECC-Tools”存储库中，并依赖于 webhook 处理程序、队列工作人员、使用预留、PR 创建逻辑或付费门实施
- 客户报告称该应用程序创建了太多 PR、计费不正确或分析代码但未产生可用结果

## 范围护栏

- 在同级“ECC-Tools”存储库中工作，而不是在“everything-claude-code”中工作
- 开始只读，除非用户明确要求修复
- 在跟踪分析消耗时不要改变不相关的计费、结账或 UI 流程
- 将应用程序生成的分支和应用程序生成的 PR 视为危险递归路径，除非另有证明
- 明确区分三件事：
  - 回购方烧伤根本原因
  - 面向客户的计费影响
  - 需要积压跟进的产品或权利差距

## 工作流程

### 1. 冻结回购范围

- 切换到同级“ECC-Tools”存储库
- 首先检查分支和本地差异
- 确定审核中的确切表面：
  - 网络钩子路由器
  - 队列生产者
  - 队列消费者
  - PR创作路径
  - 使用预约/计费路径
  - 模型路由路径

### 2. 在理论化之前追踪入口

- 首先检查 `src/index.*` 或主入口点- 在建议修复之前映射每个排队路径
- 确认哪些 GitHub 事件共享队列类型
- 确认push、pull_request、同步、注释或手动重新运行事件是否可以汇聚在同一个昂贵的路径上

### 3.追踪worker和副作用

- 检查处理分析的队列消费者或调度工作人员
- 确认排队分析是否始终以以下方式结束：
  - 公关创作
  - 分支创建
  - 文件更新
  - 高级模型调用
  - 使用增量
- 如果分析可以花费代币，然后在输出持久之前失败，则将其分类为burn-with-broken-output

### 4. 审核高信号燃烧路径

#### PR 乘法

- 检查 PR 助手和分支命名
- 检查重复数据删除、同步事件处理和现有 PR 重用
- 如果应用程序生成的分支可以重新进入分析，则将其视为优先级 0 递归风险

#### 配额绕过

- 检查检查配额的位置与保留或增加使用量的位置
- 如果在入队之前检查配额，但仅在工作人员内部收取使用费用，则将并发前门通行证视为真正的竞赛

#### 高级型号泄漏

- 检查模型选择、层分支和提供商路由- 验证当高级密钥存在时，免费或受限用户是否仍然可以访问高级分析器

#### 重试刻录

- 检查重试循环、重复队列作业和确定性失败重新运行
- 如果相同的非暂时性错误可以重复进行分析，请在质量改进之前修复它

### 5.修复刻录顺序

如果用户要求更改代码，请按以下顺序优先修复：

1.停止自动PR乘法
2.停止配额绕过
3. 阻止保费流失
4. 停止重复作业扇出和无意义的重试
5. 缩小重新运行/更新安全漏洞

除非相同的根本原因明显跨越多个文件，否则将传递范围限制为一到三个直接修复。

### 6. 用最小的证明步骤进行验证

- 仅重新运行覆盖更改路径的目标测试或集成片段
- 验证刻录路径现在是否为：
  - 被阻止
  - 重复数据删除
  - 降级为更便宜的分析
  - 或提前拒绝
- 准确说明最终状态：
  - 本地更改
  - 本地验证
  - 推
  - 已部署
  - 仍然被阻止

## 高信号故障模式

### 1. 所有触发器使用一种队列类型如果推送、PR 同步和手动审核都将同一个作业排入队列，并且工作人员总是创建 PR，则分析等于 PR 垃圾邮件。

### 2.入队后使用预留

如果在前门检查使用情况但仅在工作线程中增加，则并发请求都可以通过大门并超出配额。

### 3. 高级路径上的免费套餐

如果在密钥存在时，免费排队作业仍然可以路由到 Anthropic 或其他高级提供商，那么即使用户从未看到高级结果，这也是真正的支出泄漏。

### 4.应用生成的分支重新进入webhook

如果“pull_request.synchronize”、分支推送或评论触发在应用程序拥有的分支上运行，则应用程序可以递归地分析其自己的输出。

### 5. 持久安全之前的昂贵工作

如果系统可以花费代币，然后在 PR 创建、文件更新或分支冲突方面失败，那么它就是在燃烧成本，而没有运输价值。

## 陷阱

- 不要从广泛的回购徘徊开始；先解决 webhook -> 队列 -> 工作线程
- 不要将客户账单推断与代码支持的产品真相混为一谈
- 在包含最高消耗路径之前不要修复低价值的质量问题- 在重新运行狭窄的证明步骤之前，不要声称烧伤已修复
- 除非用户要求，否则不要推送或部署
- 如果不相关的存储库本地更改已经在进行中，请勿触摸

## 验证

- 根本原因引用了确切的文件路径和代码区域
- 修复是按烧录影响排序的，而不是代码整洁度
- 证明命令被命名
- 最终状态区分本地更改、验证、推送和部署
