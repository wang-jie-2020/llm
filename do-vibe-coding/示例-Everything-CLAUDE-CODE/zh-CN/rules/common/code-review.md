# 代码审查标准

## 目的

代码审查可确保代码合并之前的质量、安全性和可维护性。该规则定义了何时以及如何进行代码审查。

## 何时审查

**强制审核触发因素：**

- 编写或修改代码后
- 在提交任何共享分支之前
- 当安全敏感代码发生更改时（身份验证、付款、用户数据）
- 当架构发生变化时
- 合并拉取请求之前

**预审要求：**

在请求审核之前，请确保：

- 所有自动检查（CI/CD）均通过
- 合并冲突已解决
- 分支与目标分支是最新的

## 审核清单

在将代码标记为完成之前：

- [ ] 代码可读且命名良好
- [ ] 功能集中（<50 行）
- [ ] 文件具有凝聚力（<800 行）
- [ ] 无深层嵌套（>4 层）
- [ ] 错误被显式处理
- [ ] 没有硬编码的秘密或凭证
- [ ] 无 console.log 或调试语句
- [ ] 存在新功能测试
- [ ] 测试覆盖率至少达到 80%

## 安全审查触发器

**在以下情况下停止并使用安全审核代理：**

- 身份验证或授权码
- 用户输入处理
- 数据库查询- 文件系统操作
- 外部API调用
- 密码操作
- 付款或财务代码

## 查看严重级别

|水平|意义|行动|
|--------|---------|--------|
|关键 |安全漏洞或数据丢失风险 | **BLOCK** - 必须在合并之前修复 |
|高| Bug 或重大质量问题 | **警告** - 应该在合并之前修复 |
|中 |可维护性问题| **信息** - 考虑修复 |
|低|风格或小建议| **注意** - 可选|

## 代理使用

使用这些代理进行代码审查：

|代理|目的|
|--------|---------|
| **代码审阅者** |一般代码质量、模式、最佳实践 |
| **安全审查员** |安全漏洞，OWASP Top 10 |
| **打字稿审稿人** | TypeScript/JavaScript 特定问题 |
| **python-审稿人** | Python 特定问题 |
| **去审稿人** |去具体问题|
| **rust 审稿人** | Rust 特定问题 |

## 审核工作流程```
1. Run git diff to understand changes
2. Check security checklist first
3. Review code quality checklist
4. Run relevant tests
5. Verify coverage >= 80%
6. Use appropriate agent for detailed review
```
## 需要解决的常见问题

### 安全

- 硬编码凭证（API 密钥、密码、令牌）
- SQL注入（查询中的字符串连接）
- XSS 漏洞（未转义的用户输入）
- 路径遍历（未清理的文件路径）
- CSRF 保护缺失
- 身份验证绕过

### 代码质量

- 大型函数（>50 行） - 分成更小的函数
- 大文件（>800 行） - 提取模块
- 深度嵌套（>4 层） - 使用早期返回
- 缺少错误处理 - 显式处理
- 突变模式 - 更喜欢不可变的操作
- 缺少测试 - 添加测试覆盖率

### 性能

- N+1 查询 - 使用 JOIN 或批处理
- 缺少分页 - 向查询添加 LIMIT
- 无界查询 - 添加约束
- 缺少缓存 - 缓存昂贵的操作

## 批准标准

- **批准**：无严重或严重问题
- **警告**：仅限高问题（谨慎合并）
- **阻止**：发现关键问题
