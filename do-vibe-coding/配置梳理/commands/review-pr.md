对拉取请求进行全面的多角度审查。

## 用法

`/review-pr [PR 编号或 URL] [--focus=comments|tests|errors|types|code|simplify]`

如果未指定 PR，请查看当前分支的 PR。如果未指定焦点，则运行完整的审查堆栈。

## 步骤

1. 确定 PR：
   - 使用 `gh pr view` 获取 PR 详细信息、更改的文件和差异
2. 查找项目指导：
   - 查找 `CLAUDE.md`、lint 配置、TypeScript 配置、repo 约定
3.运行专门的审查代理：
   - `代码审查者`
   - `评论分析器`
   - `pr-测试分析器`
   - “沉默的失败猎手”
   - `类型设计分析器`
   - `代码简化器`
4. 汇总结果：
   - 重复删除重叠的发现
   - 按严重程度排名
5. 按严重程度分组的报告结果

## 置信度规则

仅报告置信度 >= 80 的问题：

- 严重：错误、安全性、数据丢失
- 重要提示：缺少测试、质量问题、风格违规
- 建议：仅在明确要求时提出建议
