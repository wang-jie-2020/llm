# 仪表板生成器

当任务是构建人们可以操作的仪表板时，请使用此选项。

目标不是“显示每个指标”。目标是回答：

- 健康吗？
- 瓶颈在哪里？
- 发生了什么变化？
- 人们应该采取什么行动？

## 何时使用

- “构建Kafka监控仪表板”
- “为 Elasticsearch 创建 Grafana 仪表板”
- “为此服务制作一个 SigNoz 仪表板”
- “将此指标列表变成真正的操作仪表板”

## 护栏

- 不要从视觉布局开始；从操作员问题开始
- 不要仅仅因为每个可用指标存在就将其包含在内
- 不要在没有结构的情况下混合运行状况、吞吐量和资源面板
- 不要运送没有标题、单位和合理阈值的面板

## 工作流程

### 1.定义操作问题

围绕：

- 健康/可用性
- 延迟/性能
- 吞吐量/体积
- 饱和度/资源
- 特定服务的风险

### 2. 研究目标平台架构

首先检查现有的仪表板：

- JSON结构
- 查询语言
- 变量
- 门槛样式
- 部分布局

### 3. 构建最小的有用板

推荐结构：

1. 概述
2、性能
3. 资源4. 特定服务部分

### 4.切割梳妆台面板

每个小组都应该回答一个真实的问题。如果没有，请将其删除。

## 面板集示例

### 弹性搜索

- 集群健康状况
- 分片分配
- 搜索延迟
- 索引率
- JVM堆/GC

###卡夫卡

- 经纪人数量
- 复制不足的分区
- 消息输入/输出
- 消费者滞后
- 磁盘和网络压力

### API网关/入口

- 请求率
- p50 / p95 / p99 延迟
- 错误率
- 上游健康
- 活跃连接

## 质量检查表

- [ ] 有效的仪表板 JSON
- [ ] 清除部分分组
- [ ] 头衔和单位存在
- [ ] 阈值/状态颜色有意义
- 常见过滤器存在 [ ] 变量
- [ ]默认时间范围和刷新是合理的
- [ ] 没有梳妆台，没有操作员价值
