从 $ARGUMENTS 中解析以下内容：
1. `brief` — 用户对要创建的设计的描述
2. `--max-iterations N` —（可选，默认 10）最大设计评估周期
3. `--pass-threshold N` —（可选，默认 7.5）通过的加权分数（设计的默认值较高）

## GAN 风格的设计框架

专注于前端设计质量的双代理循环（生成器 + 评估器）。没有计划者——概要就是规格。

这与 Anthropic 用于前端设计实验的模式相同，他们在其中看到了创造性的突破，例如采用 CSS 透视和门口导航的 3D 荷兰艺术博物馆。

### 设置
1.创建`gan-harness/`目录
2.直接将简写为`gan-harness/spec.md`
3. 编写以设计为中心的“gan-harness/eval-rubric.md”，特别注重设计质量和原创性

### 特定设计的评估标准```markdown
### Design Quality (weight: 0.35)
### Originality (weight: 0.30)
### Craft (weight: 0.25)
### Functionality (weight: 0.10)
```
注：原创性权重较高（0.30 vs 0.20）以推动创意突破。由于设计模式注重视觉质量，因此功能权重较低。

### 循环
与 `/project:gan-build` 第 2 阶段相同，但是：
- 跳过计划者
- 使用以设计为中心的标题
- 生成器提示强调视觉质量而不是功能完整性
- 评估员提示强调“这会赢得设计奖吗？”关于“所有功能都有效吗？”

### 与 gan-build 的主要区别
生成器被告知：“您的主要目标是视觉卓越。一个令人惊叹的半成品应用程序胜过功能丑陋的应用程序。推动创意飞跃 - 不寻常的布局、自定义动画、独特的色彩工作。”
